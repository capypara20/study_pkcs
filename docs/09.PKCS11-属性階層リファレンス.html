PKCS#11 STUDY SERIES · 03 — REFERENCE

属性階層リファレンス — 定義の系譜ツリー

全属性を「どのクラス層で定義され、継承されるか」の系譜で並べた引き表。各属性には 誰が値を決めるか のマーカーを付す。OASIS PKCS#11 v3.0 base / v3.2 spec 準拠。

⚠ 読む前の注意 — これは「定義の系譜」であって「格納構造」ではない

この階層は仕様書上で属性がどの層で定義・継承されるかを表す。実行時の各オブジェクトは、継承ぶんも含めた全属性をフラットな属性バッグとして持つ。C_GetAttributeValue に階層をたどる操作は存在せず、どの属性も直接指定して読む。ツリーは「探す場所の地図」であって「データの形」ではない。

書あなたがテンプレートで指定 黙デフォルトあり（省略可） 生トークンが生成（書けない） 読読取専用・トークン付与 粘粘着性（一方通行の変更）
▸Object— 全オブジェクトの根CKA_CLASS が型を決める第1識別子
CKA_CLASS書オブジェクトの種類（CKO_*）。生成後は不変。テンプレートの事実上の必須第一属性
▸Storage — 保存オブジェクト共通Data / Certificate / Key が継承可視性・永続性・寿命を司る層
CKA_TOKEN書黙永続(true) / セッション限り(false)。デフォルトは CK_FALSE＝揮発
CKA_PRIVATE書黙要ログイン(true)か。デフォルトはトークン依存（他属性に連動しうる）
CKA_MODIFIABLE書黙変更可か。デフォルト CK_TRUE。生成時のみ指定可
CKA_LABEL書人間可読ラベル。生成後に実質的に変更できるのはほぼこれだけ。検索キーとして多用
CKA_COPYABLE書黙C_CopyObject で複製できるか。true→false の一方通行（v2.40〜）
CKA_DESTROYABLE書黙C_DestroyObject で消せるか。デフォルト CK_TRUE
CKA_UNIQUE_ID読トークンが振る一意ID。v3.0で追加。テンプレートに入れると CKR_ATTRIBUTE_READ_ONLY
▸DataCKO_DATA最小構成。用途フラグも保護属性もない
CKA_APPLICATION書黙管理アプリケーションの記述（RFC 2279 文字列）
CKA_OBJECT_ID書黙DER符号化 OID による分類
CKA_VALUE書黙中身のバイト列そのもの（デフォルトは空）
▸Certificate — 証明書共通CKO_CERTIFICATE用途フラグ・保護属性なし＝「公開が前提の入れ物」
CKA_CERTIFICATE_TYPE書第2の識別子（CKC_X_509 等）。生成後不変
CKA_TRUSTED書SO ログイン時のみ true に設定可。トラストアンカーの印
CKA_CERTIFICATE_CATEGORY書黙未指定 / トークン利用者 / CA / その他エンティティ の分類
CKA_CHECK_VALUE読証明書の検査値（SHA-1ハッシュ先頭3バイト）
CKA_START_DATE / CKA_END_DATE書黙有効期間（デフォルトは空）
CKA_PUBLIC_KEY_INFO黙読DER符号化 SubjectPublicKeyInfo
▸X.509 公開鍵証明書CKC_X_509SUBJECT と VALUE が必須
CKA_SUBJECT書必須。DER符号化 subject 名
CKA_VALUE書必須。BER符号化の証明書まるごと（CKA_URL 利用時は空も可）
CKA_ID書黙鍵ペア・証明書を束ねる紐付けキー。同一 CKA_ID で三点セットを結ぶ
CKA_ISSUER書黙DER符号化 issuer 名
CKA_SERIAL_NUMBER書黙DER符号化シリアル番号
CKA_URL書黙証明書本体を外部URLに置く場合の参照
CKA_HASH_OF_SUBJECT_PUBLIC_KEY書黙subject 公開鍵のハッシュ（URL運用時に照合用）
CKA_HASH_OF_ISSUER_PUBLIC_KEY書黙issuer 公開鍵のハッシュ
CKA_NAME_HASH_ALGORITHM書黙上記ハッシュのアルゴリズム。デフォルト SHA-1
CKA_JAVA_MIDP_SECURITY_DOMAIN書黙Java MIDP 用ドメイン分類（レガシー・通常は未指定）
▸Key — 鍵3クラス共通公開鍵 / 秘密鍵 / 共通鍵 が継承アルゴリズム識別と鍵ライフサイクルの層
CKA_KEY_TYPE書黙アルゴリズム（CKK_RSA / CKK_EC / CKK_AES …）。CKA_CLASS（役割）とは独立の軸。鍵生成ではメカニズムから確定することが多い
CKA_ID書黙公開鍵・秘密鍵・証明書をペア紐付けするキー
CKA_START_DATE / CKA_END_DATE書黙鍵の有効期間
CKA_DERIVE書黙この鍵から別の鍵を導出できるか。デフォルト CK_FALSE
CKA_LOCAL読トークン内で生成されたか。外から入れた鍵は false。鍵の出自証明
CKA_KEY_GEN_MECHANISM読どのメカニズムで生成されたか（非ローカル鍵は CK_UNAVAILABLE_INFORMATION）
CKA_ALLOWED_MECHANISMS書黙この鍵で使えるメカニズムをホワイトリスト限定
▸公開鍵CKO_PUBLIC_KEYSENSITIVE / EXTRACTABLE は存在しない
用途フラグ
CKA_ENCRYPT書黙暗号化に使えるか
CKA_VERIFY書黙署名検証に使えるか（署名が付録のタイプ）
CKA_VERIFY_RECOVER書黙データ回復付き検証に使えるか
CKA_WRAP書黙他鍵をラップ（暗号化して包む）できるか
信頼・制約
CKA_SUBJECT書黙DER符号化 subject 名
CKA_TRUSTED書SO のみ true 化可。WRAP_WITH_TRUSTED 鍵のラップ先として信頼される
CKA_WRAP_TEMPLATE書黙この鍵でラップできる鍵の属性条件を制限
CKA_PUBLIC_KEY_INFO黙読DER符号化 SubjectPublicKeyInfo
▸RSA 公開鍵CKK_RSA鍵ペアの鍵長はここで決まる
CKA_MODULUS生法 n（鍵生成時はトークンが生成）
CKA_MODULUS_BITS書生鍵ペア生成時に公開鍵テンプレートで指定（例: 2048）。生成後は読取専用
CKA_PUBLIC_EXPONENT書黙公開指数 e。省略時はメカニズムが 0x10001 (65537) を補う
▸EC 公開鍵CKK_EC
CKA_EC_PARAMS書曲線の指定（DER符号化。鍵ペア生成時は公開鍵テンプレートで指定）
CKA_EC_POINT生公開点 Q（DER符号化）
▸秘密鍵CKO_PRIVATE_KEY保護属性の本丸。「HSMから出せない」を構成する層
用途フラグ
CKA_DECRYPT書黙復号に使えるか
CKA_SIGN書黙署名に使えるか
CKA_SIGN_RECOVER書黙データ回復付き署名に使えるか
CKA_UNWRAP書黙ラップされた鍵を取り込めるか
保護属性 — 粘着ペア
CKA_SENSITIVE書粘true で秘密値を C_GetAttributeValue で読めなくする。false → true のみ。戻せない
CKA_EXTRACTABLE書粘false でラップによる持ち出しも禁止。true → false のみ。戻せない
CKA_ALWAYS_SENSITIVE読生まれてから一度も SENSITIVE=false だったことがないか。履歴の証明
CKA_NEVER_EXTRACTABLE読生まれてから一度も EXTRACTABLE=true だったことがないか
粘着の向き： SENSITIVE: false ──→ true（不可逆） ／ EXTRACTABLE: true ──→ false（不可逆）。この2本の一方通行が「鍵の非可逆な封印」を構成する。
追加の防御・認証
CKA_WRAP_WITH_TRUSTED書黙粘CKA_TRUSTED=true の鍵でしかラップさせない。false → true のみ
CKA_ALWAYS_AUTHENTICATE書黙使用のたびに再認証（C_Login CKU_CONTEXT_SPECIFIC）を要求
CKA_UNWRAP_TEMPLATE書黙この鍵でアンラップして生まれる鍵に強制する属性条件
CKA_SUBJECT書黙DER符号化 subject 名
CKA_PUBLIC_KEY_INFO黙読対応する公開鍵の SubjectPublicKeyInfo。v2.40以降、秘密鍵から公開鍵を復元できる建付け
▸RSA 秘密鍵CKK_RSAMODULUS_BITS は指定しない（罠①）
CKA_MODULUS生法 n。トークンが必ず返せる2属性のうち1つ
CKA_PRIVATE_EXPONENT生秘密指数 d。もう1つの必須保持属性（SENSITIVE=true なら読めない）
CKA_PUBLIC_EXPONENT生e。v2.40以降トークンは必ず保持（公開鍵復元のため）
CKA_PRIME_1 / CKA_PRIME_2生素数 p, q（CRT用。保持はトークン次第）
CKA_EXPONENT_1 / CKA_EXPONENT_2生d mod (p−1), d mod (q−1)
CKA_COEFFICIENT生q⁻¹ mod p
罠①の裏付け：秘密鍵テンプレートに CKA_MODULUS_BITS は書かない。秘密鍵はペアの一部としてのみ生成され、鍵長は公開鍵側の CKA_MODULUS_BITS で決まる。
▸EC 秘密鍵CKK_EC
CKA_EC_PARAMS生曲線（ペア生成では公開鍵側の指定から引き継がれる）
CKA_VALUE生秘密値 d（ANSI X9.62整数）
▸共通鍵CKO_SECRET_KEY公開/秘密の両側の用途を1つの鍵が担う
用途フラグ — 両側ぶんを持つ
CKA_ENCRYPT / CKA_DECRYPT書黙暗号化・復号
CKA_SIGN / CKA_VERIFY書黙MAC の生成・検証（共通鍵では「署名」＝MAC）
CKA_WRAP / CKA_UNWRAP書黙他鍵のラップ・アンラップ（KEK 用途）
保護属性 — 秘密鍵と同じ体系
CKA_SENSITIVE書粘false → true のみ。一度「秘匿」にした鍵を平文可視には戻せない
CKA_EXTRACTABLE書粘true → false のみ
CKA_ALWAYS_SENSITIVE / CKA_NEVER_EXTRACTABLE読履歴の証明（生成時からの導出）
CKA_WRAP_WITH_TRUSTED書黙粘信頼済み鍵限定ラップ。false → true のみ
共通鍵だけの追加分
CKA_CHECK_VALUE読鍵検査値（KCV）。鍵の同一性確認に使う
CKA_TRUSTED書SO のみ。ラップ先として信頼される共通鍵
CKA_WRAP_TEMPLATE / CKA_UNWRAP_TEMPLATE書黙ラップ／アンラップ対象の属性条件を強制
CKA_DERIVE_TEMPLATE書黙この鍵から導出される鍵に強制する属性条件。v3.0で追加
▸AES 鍵CKK_AES
CKA_VALUE_LEN書生鍵長（16/24/32バイト）。C_GenerateKey 時にテンプレートで指定。生成後は読取専用
CKA_VALUE生鍵バイトそのもの（C_GenerateKey ではトークンが生成。C_CreateObject での持ち込み時のみ自分で書く）
▸ 裏取りの範囲（正直な明示）

粘着性（SENSITIVE の false→true 一方通行）、RSA秘密鍵での MODULUS_BITS 不在、PUBLIC_EXPONENT デフォルト 65537、CKA_UNIQUE_ID の v3.0 追加は一次仕様の原文で確認済み。一方、属性のクラス層への割り当て全体はこちらで構成した整理であり、DH/DSA/GOST 等の鍵種別、CKO_MECHANISM / CKO_HW_FEATURE / CKO_PROFILE といった非保存系オブジェクトは意図的にスコープ外。実装前は v3.2 spec §4（Objects）§6（Mechanisms）の該当表と突き合わせること。デフォルト値と粘着の強制はベンダー差があり、SoftHSM2 と本番HSMで挙動が違いうる。
