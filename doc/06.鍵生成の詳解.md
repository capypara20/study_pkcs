# 06. 鍵生成の詳解（各種アルゴリズム）

署名も暗号もまず「鍵が無いと始まらない」。ここでは PKCS#11 / cryptoki での
**鍵生成の考え方**と、**アルゴリズムごとの作り方**を深掘りする。
（コードは `src/ops/keygen.rs` と対応）

---

## 0. 鍵生成で決めるのは「2つだけ」

どのアルゴリズムでも、鍵生成で指定するのは次の 2 つだけ。

1. **メカニズム(Mechanism)** … どのアルゴリズムで作るか
   例: `RsaPkcsKeyPairGen`, `EccKeyPairGen`, `AesKeyGen`
2. **テンプレート(Template)** … 作る鍵に貼る「属性(Attribute)の配列」
   例: `Token(true)`(永続保存), `Sign(true)`(署名可), `Extractable(false)`(持出禁止)

```rust
// 非対称(鍵ペア): メカニズム + 公開鍵テンプレ + 秘密鍵テンプレ
session.generate_key_pair(&mechanism, &pub_template, &priv_template)?;
// 対称(単一鍵):   メカニズム + テンプレ1つ
session.generate_key(&mechanism, &template)?;
```

戻り値は **鍵の中身ではなくハンドル(整理番号)**。秘密鍵は HSM から出てこない。

---

## 1. 2系統：非対称(鍵ペア) と 対称(単一鍵)

| | 非対称鍵 | 対称鍵 |
|---|---|---|
| 例 | RSA, EC, Ed25519, X25519 | AES, 3DES, Generic-Secret |
| 鍵の数 | **2つ**(公開鍵+秘密鍵)がペアで出る | **1つ** |
| メソッド | `generate_key_pair` | `generate_key` |
| テンプレ | 2つ(pub用/priv用) | 1つ |
| 主な用途 | 署名/検証, 鍵共有, 公開鍵暗号 | 暗号化/復号, 鍵ラップ, HMAC |
| 長さ指定 | RSA=`ModulusBits`, EC=`EcParams`(曲線) | `ValueLen`(バイト数) |

**覚え方**: 非対称=ペア生成=テンプレ2枚 / 対称=単数生成=テンプレ1枚。

---

## 2. 属性(Attribute)の意味 — テンプレの中身

鍵テンプレでよく使う属性。**「保存場所」「種別」「能力」「保護」**の4グループで捉える。

### (a) 保存場所・識別
| 属性 | 意味 |
|---|---|
| `Token(true)` | トークンに**永続保存**。`false`ならセッション限り(切断で消える) |
| `Label("...")` | 人間が読む名札。検索(`find_key`)のキーに使う |
| `Id(...)` | バイト列の ID。証明書と鍵の紐付け等に使う |

### (b) 鍵種別（対称鍵やラップ時に明示）
| 属性 | 意味 |
|---|---|
| `Class(...)` | オブジェクト種別。`PRIVATE_KEY`/`PUBLIC_KEY`/`SECRET_KEY` |
| `KeyType(...)` | 鍵アルゴリズム。`RSA`/`EC`/`AES`/`GENERIC_SECRET` 等 |

> `generate_key_pair`/`generate_key` では、メカニズムから種別が決まるので
> Class/KeyType を省略できることが多い（unwrap/derive 時は明示が要る）。

### (c) 能力フラグ — 「その鍵で何ができるか」
| 属性 | 許可される操作 |
|---|---|
| `Sign(true)` | 署名（秘密鍵/HMAC鍵） |
| `Verify(true)` | 署名検証（公開鍵/HMAC鍵） |
| `Encrypt(true)` | 暗号化 |
| `Decrypt(true)` | 復号 |
| `Wrap(true)` | 他の鍵をラップ(暗号化)できる |
| `Unwrap(true)` | ラップされた鍵を取り込める |
| `Derive(true)` | 鍵導出(ECDH等)に使える |

> 能力フラグは **最小限だけ true** にするのが鉄則(最小権限)。
> 例: 署名専用の秘密鍵に `Decrypt(true)` は付けない。

### (d) 保護 — HSM の肝
| 属性 | 意味 |
|---|---|
| `Private(true)` | このオブジェクトを見るにはログインが要る |
| `Sensitive(true)` | 値(`CKA_VALUE`)を**読み出せない**ようにする |
| `Extractable(false)` | 鍵を(ラップしてでも)**持ち出せない**ようにする |

> `Sensitive(true)` + `Extractable(false)` が「鍵は金庫から出ない」を実現する組み合わせ。
> バックアップで持ち出したい鍵だけ `Extractable(true)` にする（→ `wrap` でラップして取り出す）。

## 3. アルゴリズム別の作り方

### 3-1. RSA（署名・暗号の定番）
- メカニズム: `RsaPkcsKeyPairGen`
- 長さ: `ModulusBits(2048/3072/4096…)` ＋ 公開指数 `PublicExponent`(=65537)
- 後段: 署名は `Sha256RsaPkcs`、暗号は `RsaPkcs`/`RsaPkcsOaep`

```rust
let pub_t = vec![
    Attribute::Token(true), Attribute::Verify(true), Attribute::Encrypt(true),
    Attribute::ModulusBits(2048.into()),
    Attribute::PublicExponent(vec![0x01,0x00,0x01]), // 65537
    Attribute::Label(b"my-rsa".to_vec()),
];
let priv_t = vec![
    Attribute::Token(true), Attribute::Private(true),
    Attribute::Sign(true), Attribute::Decrypt(true),
    Attribute::Sensitive(true), Attribute::Extractable(false),
    Attribute::Label(b"my-rsa".to_vec()),
];
session.generate_key_pair(&Mechanism::RsaPkcsKeyPairGen, &pub_t, &priv_t)?;
```
CLI: `gen-rsa 2048 my-rsa`

### 3-2. EC / ECDSA（短い鍵で強い。主流）
- メカニズム: `EccKeyPairGen`
- 長さの代わりに **曲線の OID を `EcParams` で**渡す
- 後段の署名: `EcdsaSha256`

| 曲線名 | 別名 | OID | DER(EcParams) |
|---|---|---|---|
| p256 | prime256v1 / secp256r1 | 1.2.840.10045.3.1.7 | `06 08 2A 86 48 CE 3D 03 01 07` |
| p384 | secp384r1 | 1.3.132.0.34 | `06 05 2B 81 04 00 22` |
| p521 | secp521r1 | 1.3.132.0.35 | `06 05 2B 81 04 00 23` |
| secp256k1 | (Bitcoin等) | 1.3.132.0.10 | `06 05 2B 81 04 00 0A` |

```rust
let ec_params = vec![0x06,0x08,0x2A,0x86,0x48,0xCE,0x3D,0x03,0x01,0x07]; // p256
let pub_t = vec![Attribute::Token(true), Attribute::Verify(true),
                 Attribute::EcParams(ec_params), Attribute::Label(b"my-ec".to_vec())];
let priv_t = vec![Attribute::Token(true), Attribute::Private(true), Attribute::Sign(true),
                  Attribute::Sensitive(true), Attribute::Extractable(false),
                  Attribute::Label(b"my-ec".to_vec())];
session.generate_key_pair(&Mechanism::EccKeyPairGen, &pub_t, &priv_t)?;
```
CLI: `gen-ec p256 my-ec` / `gen-ec secp256k1 btc`
（`keygen::ec_curve_oid("p256")` が上記の DER を返す）

> **OID の DER って何?**: 曲線の名前を表す数値列(OID)を、ASN.1 という規格で
> バイト列に符号化したもの。先頭 `06` が「これは OID」、次が長さ、残りが中身。
> 中身は丸暗記不要。上の表からコピーすればよい。

### 3-3. Ed25519（最新の署名。高速・安全）
- メカニズム: `EccEdwardsKeyPairGen`
- `EcParams` = edwards25519 の OID(1.3.101.112) → `06 03 2B 65 70`
- 後段の署名: `Eddsa`(EdDSA。ハッシュ込みなので別途 SHA は不要)

CLI: `gen-ed25519 my-ed`
> トークンによっては `EcParams` に OID でなく曲線名文字列 `"edwards25519"` を
> 要求する実装もある。エラーが出たら名前文字列を試す。

### 3-4. X25519（署名ではなく「鍵共有」用）
- メカニズム: `EccMontgomeryKeyPairGen`
- `EcParams` = curve25519 の OID(1.3.101.110) → `06 03 2B 65 6E`
- 能力は `Sign` ではなく **`Derive(true)`**（ECDH で共有鍵を作るため）
- 後段: `derive`(ECDH) で共有 AES 鍵を導出

CLI: `gen-x25519 my-x`

### 3-5. AES（対称鍵。暗号化・鍵ラップ）
- メカニズム: `AesKeyGen`、長さは `ValueLen`(バイト): 16/24/32 = AES-128/192/256
- 後段: 暗号は `AesCbcPad`/`AesGcm`、鍵ラップは `AesKeyWrapPad`

```rust
let t = vec![Attribute::Token(true), Attribute::ValueLen(32.into()),
             Attribute::Encrypt(true), Attribute::Decrypt(true),
             Attribute::Wrap(true), Attribute::Unwrap(true),
             Attribute::Label(b"my-aes".to_vec())];
session.generate_key(&Mechanism::AesKeyGen, &t)?; // ← 単数生成
```
CLI: `gen-aes 32 my-aes`

### 3-6. Generic-Secret（HMAC 用のただのバイト列鍵）
- メカニズム: `GenericSecretKeyGen`、長さ `ValueLen`
- `Sign`/`Verify` を true（HMAC の生成・検証に使う）

CLI: `gen-hmac 32 my-hmac`

## 4. 「鍵 → 署名」の対応（ここがゴール）

鍵の種類によって、署名で使うメカニズムが変わる。
本プログラムの `sign` は **鍵の KeyType を読んで自動で選ぶ**ので、
利用者は鍵ラベルを渡すだけでよい（`src/ops/sign.rs`）。

| 鍵生成 | KeyType | 署名メカニズム | 検証メカニズム |
|---|---|---|---|
| `gen-rsa` | RSA | `Sha256RsaPkcs` | 同左 |
| `gen-ec` | EC | `EcdsaSha256` | 同左 |
| `gen-ed25519` | EC_EDWARDS | `Eddsa` | 同左 |
| `gen-aes` / `gen-hmac` | (対称) | 署名ではなく暗号/HMAC | — |
| `gen-x25519` | EC_MONTGOMERY | 署名不可(鍵共有専用) | — |

### 通しで試す（SoftHSM 前提）
```bash
# RSA
cargo run --bin hsm -- gen-rsa 2048 rsakey
cargo run --bin hsm -- sign   rsakey "hello"      # → sig(hex)
cargo run --bin hsm -- verify rsakey "hello" <hex>

# EC (P-256)
cargo run --bin hsm -- gen-ec p256 eckey
cargo run --bin hsm -- sign   eckey "hello"

# Ed25519
cargo run --bin hsm -- gen-ed25519 edkey
cargo run --bin hsm -- sign edkey "hello"

# 確認
cargo run --bin hsm -- list
cargo run --bin hsm -- attrs eckey
```

## 5. つまずきポイント
- **鍵長/曲線の指定場所が違う**: RSA=`ModulusBits`、EC=`EcParams`、対称=`ValueLen`。
- **能力フラグ不足でエラー**: 署名鍵に `Sign(true)` が無い、ラップ元に `Extractable(true)` が
  無い、等。操作が `CKR_KEY_FUNCTION_NOT_PERMITTED` 等で弾かれたら、まず属性を疑う。
- **トークンが対応していない**: `cargo run --bin hsm -- info` の対応メカニズム一覧に
  目的の `*KeyPairGen` が無ければ、そのトークンでは作れない（実機 HSM で要確認）。
- **Token(true) を忘れる**: セッションが切れると鍵が消える。永続化したいなら必須。
